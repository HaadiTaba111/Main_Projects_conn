# سیستم یکپارچهٔ معاملهٔ فیوچرز — نسخهٔ تمیز و حرفه‌ای

هدف: یک معماری تمیز که **بهترین بخش‌های هر نسخه** را کنار هم بگذارد، با داشبورد،
و مسیر بهینه از «داده» تا «اجرا» تا «تحلیل». همه‌چیز تا عبور از دروازهٔ اعتبارسنجی
**PAPER** است.

```
┌─────────────── لایهٔ داده ───────────────┐
│ Bybit (صرافیِ سیستم واقعی تو) / Binance / CSV / Synthetic │
└──────────────┬───────────────┘
               ▼
┌─────────────── لایهٔ سیگنال ─────────────
│ ۵ خانوادهٔ مدل + consensus k‑از‑M + sweep چند تایم‌فریم   │
│ (apps/futures-scalp-lab/scalplab: models, sweep, auto)   │
└──────────────┬───────────────┘
               ▼
┌─────────────── لایهٔ ریسک (قوانین تو) ───┐
│ سقف ۴ همزمان · circuit‑breaker (۲ ضرر) · استاپ ATR · trailing │
│ (scalplab/engine.py) — خروجی: سیگنالِ تأییدشده            │
└──────────────┬───────────────┘
               ▼
┌─────────────── لایهٔ اجرا ───────────────┐
│ paper‑broker (پیش‌فرض)  ←→  real‑broker امنِ Bybit (فقط با اجازهٔ صریح) │
│ kill‑switch · live‑only · webhook امن · audit   (apps/futures-pwa)     │
└──────────────┬───────────────┘
               ▼
┌─────────────── لایهٔ ثبت/تحلیل/نمایش ────┐
│ signals/outcomes/trades *.jsonl + report_*  │
│ داشبورد: /scalp‑lab (و /poet برای DSA)      │
└──────────────────────────────────┘
```

## چرا این تقسیم‌بندی؟
- **داده و سیگنال** در Python (`scalplab`) چون چرخهٔ علمی/سویپ سریع است.
- **اجرا** در PWA تو (`apps/futures-pwa`) چون از قبل real‑broker امنِ Bybit دارد.
- **ریسک** به‌صورت لایهٔ مشترک: قوانین تو در `engine.py`؛ وقتی به real‑broker وصل
  می‌شویم، همان قوانین جلوی ارسال اعمال می‌شوند (نه اینکه دوباره نوشته شوند).

## اجزای بازیابی‌شده از ریپوی پشتیبان `HaadiTaba111/-`
- `apps/futures-pwa/` ← کپی قابل‌ویرایشِ `futures.zip` (اپ وب تو با paper/real‑broker).
- `archive/raw/futures.zip`, `archive/raw/finetun_farsi_shaer (2).zip` ← ZIPهای دست‌نخورده.
- `apps/phone-agent/` ← پایهٔ بازسازی «مامور گوشی» (مرکز مغز امن).

## مسیر بهینه (گام‌به‌گام)
1. **دادهٔ واقعی:** `--data bybit` (یا binance) روی PC/VPS با `--light`.
2. **سویپ:** `sweep --data bybit --tfs 1,5,15 --horizons 4,8,16` → سناریوی برتر.
3. **تصمیم:** فقط اگر سناریوی برتر خالصِ مثبتِ پایدار (CI بالای صفر، بهتر از کنترل) شد.
4. **اجرا:** اتصال موتور ریسک به real‑broker/webhook؛ ابتدا سایز کوچک؛ kill‑switch روشن.

## یادآوری دربارهٔ «+۵٪ بازار»
بالا رفتن کلی بازار (فیوچرز/اسپات) یعنی **بتای بازار** سود داده، نه لزوماً استراتژی ما.
معیار ما همچنان «خالصِ مثبتِ پایدار پس از کارمزد، بهتر از کنترل» است — نه هم‌جهتی با بازار.
