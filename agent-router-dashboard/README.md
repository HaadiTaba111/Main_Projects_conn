# AgentRouter Hub — داشبورد مدیریت API

داشبورد فارسی و راست‌چین برای مدیریت APIهایی که از **Agent Router** می‌گیرید (سازگار با OpenAI API).

## اجرا
```bash
cd agent-router-dashboard
python3 -m http.server 8000
# باز کنید: http://localhost:8000
```
یا فایل `index.html` را مستقیم در مرورگر باز کنید.

## امکانات
- **مدیریت چند کلید API**: افزودن/ویرایش/حذف، کلید فعال، Base URL جدا برای هر کلید، کپی و ماسک کلید
- **تست اتصال و همگام‌سازی مدل‌ها** از `GET /v1/models` همراه با سنجش Latency
- **آزمایشگاه چت Streaming** با تنظیم مدل، System Prompt، Temperature و Max Tokens + دکمه توقف
- **داشبورد آماری**: تعداد کلید/مدل/درخواست، توکن مصرفی، نمودار ۷ روز اخیر، حالت دمو
- **لاگ کامل درخواست‌ها** (موفق/خطا، زمان پاسخ، توکن) با خروجی JSON
- **تاریخچه مکالمات** با کپی پاسخ و خروجی چت
- **نمونه‌کد آماده** cURL / Python / JavaScript بر اساس کلید و مدل فعال
- **بکاپ‌گیری و بازیابی** همه داده‌ها (JSON) و ریست کامل
- کاملاً **بدون بک‌اند**: کلیدها فقط در LocalStorage مرورگر شما می‌مانند.

## نکات
- Base URL پیش‌فرض: `https://agentrouter.org/v1`
- اگر مرورگر خطای CORS داد، یعنی سرویس برای دامنه شما CORS باز نکرده؛ از یک پروکسی/بک‌اند واسط استفاده و آدرس آن را به‌عنوان Base URL وارد کنید.
- برآورد توکن در حالت Streaming (وقتی سرور usage نفرستد) تقریبی است.

## 👁️⌨️ چشم و دست (تب جدا — لاگ‌محور و Shortcut‌محور)
- **چشم ≠ دوربین:** اولویت با **فایل لاگ صفحه** است (`{"type":"page","url":...,"buttons":[...],"inputs":[...],"errors":[...]}` به‌صورت JSON-lines). داشبورد لاگ را محلی Parse/dedupe و خلاصه می‌کند و فقط خلاصه را برای مدل می‌فرستد → سریع‌تر و کم‌توکن‌تر. DOM/HTML رتبه دوم، اسکرین‌شات سوم و **دوربین فقط عنداللزوم** است.
- **دست ≠ کلیک شانسی:** اولویت با **Shortcut**هاست (`ctrl+l`, `Tab`, `ctrl+shift+t` و...) از طریق `xdotool` روی اوبونتو؛ ماکرو و تایپ متن هم هست. پیشنهاد Shortcut مدل، قبل از اجرا نیاز به تأیید انسان دارد.

### اجرا روی اوبونتو 22.04
```bash
cd agent-router-dashboard/eye-hand-service
bash install-ubuntu22.sh          # xdotool + سرویس systemd کاربر روی پورت 8765
python3 ../tools/make_sample_page_log.py   # لاگ نمونه در /tmp/page.log (اختیاری، برای تست)
systemctl --user status eye-hand.service
```
بعد در داشبورد: تب **«چشم و دست»** → «خواندن زنده لاگ از اوبونتو» → «پرسیدن از مدل» → Shortcut پیشنهادی را تأیید و اجرا کنید.
لاگ واقعی صفحه را هر تولیدکننده‌ای می‌تواند بنویسد (اکستنشن/اسکریپت Playwright/Puppeteer که بعد از هر تغییر صفحه، یک خط JSON بالا را append کند).

## 🧩 معماری ماژولار (API + Ollama + مترجم + دسترسی + مانیتور زنده)
هر قابلیت یک ماژول جدا در `modules/` است: `permissions.js` (دسترسی/پروفایل)، `activity.js` (مانیتور زنده)، `providers.js` (API+Ollama+جستجو)، `agent.js` (ایجنت/مترجم/ماوس)، `modules-ui.js` (رجیستری ماژول‌ها). تب‌ها هم موضوعی‌اند تا داشبورد شلوغ نشود: ایجنت | فعالیت زنده | ماژول‌ها | دسترسی‌ها | چشم‌ودست | ...

- **دو مدل هم‌زمان:** در تب «ایجنت و روتینگ مدل‌ها» مدل اصلی و مترجم را جدا انتخاب می‌کنید؛ پیشوند `api:` یعنی AgentRouter و `ollama:` یعنی Ollama محلی (`http://127.0.0.1:11434`). مثال: سؤال فارسی → مترجم (مثلاً Qwen روی Ollama) → DeepSeek R1 (API) → مترجم → جواب فارسی.
- **دسترسی‌ها از شما اجازه می‌گیرند:** همه دسترسی‌ها پیش‌فرض خاموش‌اند؛ ایجنت هنگام نیاز مودال «فعال کن / فقط همین بار / رد» نشان می‌دهد.
- **پروفایل دسترسی:** در تب «دسترسی‌ها و پروفایل‌ها» پروفایل آماده (فقط مشاهده / مرورگر با Shortcut / تحقیق اینترنتی / کنترل کامل) انتخاب کنید یا از وضعیت فعلی، پروفایل با نام دلخواه بسازید و بعداً با یک انتخاب اعمالش کنید.
- **فعالیت زنده:** تب «فعالیت زنده» + نشانگر بالای داشبورد نشان می‌دهد ایجنت الان در کدام مرحله است (ترجمه، جستجو، فکرکردن مدل، Shortcut...) و چه کرده/کجا خطا خورده.
- **جستجوی اینترنت:** ماژول جدا و دسترسی‌دار؛ از `POST /search` سرویس اوبونتو (DuckDuckGo Lite) انجام می‌شود و نتایج قبل از مدل اصلی به او داده می‌شود.
- اسکرین‌شات/دوربین/ماوس ماژول‌های جدا و پیش‌فرض خاموش‌اند (در تب ماژول‌ها).

## ⛓️ زنجیره ایجنت، Import/Export پروفایل، و 🛑 Emergency Stop
- **چشم و دست به چه کسی وصل‌اند؟** چشم → Parser (بدون مدل) → خلاصه → (در صورت نیاز مترجم فقط متن را ترجمه می‌کند) → **مدل اصلی تصمیم‌گیر** (مثل DeepSeek R1) که `ACTION:` می‌دهد → ACTION پس از چک در وایت‌لیست Shortcutها → دست. مترجم هیچ‌وقت دست را کنترل نمی‌کند؛ توضیح تصمیم برای کاربر از مسیر مترجم برمی‌گردد.
- **زنجیره ایجنت‌ها** (تب ایجنت): پریست‌های ترجمه+DeepSeek / چشم→تصمیم→Shortcut / جستجو→تحلیل→نقد، یا زنجیره دستی با مدل و نقش جدا برای هر قدم؛ خروجی هر قدم ورودی بعدی است و همه در «فعالیت زنده» دیده می‌شود.
- **Import/Export پروفایل‌ها** (تب دسترسی‌ها): خروجی JSON از دسترسی‌ها+پروفایل‌ها+وضعیت ماژول‌ها و ورود مجدد آن روی هر سیستم.
- **🛑 STOP اضطراری:** دکمه قرمز همیشه‌نمایان پایین صفحه و میانبر `Ctrl+Shift+E`. همه fetchهای در حال انجام Abort می‌شوند، دوربین خاموش می‌شود، ایجنت/زنجیره بین قدم‌ها می‌ایستد و به سرویس اوبونتو فرمان توقف می‌رود؛ تا وقتی خودتان با تأیید Resume نکنید، سرویس اوبونتو هیچ فرمان دستی اجرا نمی‌کند (HTTP 423) و داشبورد هم چیزی نمی‌فرستد. زدن دوباره همان دکمه = پرسش برای Resume.

## 🧠 حافظه تجربه و مهارت‌ها (کار روتین بدون «مغز»)
تب «حافظه و مهارت‌ها»: هر بار چشم وضعیتی را می‌بیند، مدل اصلی تصمیم می‌گیرد، شما ACTION را اجرا و موفق‌بودنش را تأیید می‌کنید، آن وضعیت (امضای URL+عنوان+فیلدها) + عمل، به‌صورت **مهارت** ذخیره می‌شود. دفعات بعد همان وضعیت، مهارت پیشنهاد و **بدون صدازدن مدل اصلی** اجرا می‌شود (شمارنده «دفعات دورزدن مغز» و نرخ موفقیت در همان تب است). اگر مهارت ناموفق شود، داشبورد پیشنهاد می‌دهد از مغز بپرسد. مهارت دستی هم از ماکرو ساخته می‌شود؛ همه مهارت‌ها قابل فعال/غیرفعال و حذف‌اند و دفتر تجربه‌ها همه رویدادهای done را ثبت می‌کند.

## ⏰ ساعت/زمان‌بندی، 🎓 آموزش توسط کاربر، 🖥️ منابع و 🌀 نگهبان لوپ
- بالای داشبورد ساعت و تاریخ زنده است؛ تب «فعالیت زنده» بخش زمان‌بندی دارد (اجرای مهارت/چک چشم/زنجیره هر N دقیقه، فقط وقتی داشبورد باز است؛ تسک ازدست‌رفته گزارش می‌شود).
- مهارت‌ها با **تطبیق فازی ≥۸۰٪** هم پیدا می‌شوند (شباهت URL+عنوان+فیلدها+دکمه‌ها).
- **آموزش توسط خودم** (تب حافظه): قدم‌ها را خودتان می‌نویسید، تست می‌گیرید و فعال می‌کنید — برای روتین‌های ثابت از گفتن به مدل بهتر است (صفر توکن، قطعی، امن). مدل برای کارهای تازه/متغیر بهتر است؛ ترکیب هر دو حالت پیش‌فرض داشبورد است.
- **منابع اوبونتو** (`GET /resources` سرویس): CPU/RAM/دیسک/Load زنده در تب فعالیت؛ حد RAM قابل تنظیم است و بالای آن تسک/ایجنت رد می‌شود؛ دکمه آزادسازی RAM مدل‌های Ollama هم هست.
- **نگهبان لوپ:** تکرار یک عمل روی یک وضعیت ≥۳ بار در ۲ دقیقه = مکث خودکار + درخواست کمک از انسان (ادامه بده / از مغز بپرس)؛ همه در فعالیت زنده ثبت می‌شود.

## 👁️ نظارت کامل در داشبورد (بدون کنسول/VSCode)
همه‌چیز در داشبورد دیده می‌شود: فعالیت ایجنت/مدل/مترجم/چشم/دست (تب فعالیت زنده)، خطاهای JS و Promiseها همان‌جا ثبت می‌شوند و **لاگ سرویس اوبونتو** هم از `GET /logs` هر ۵ ثانیه داخل همان تب می‌آید. کنسول VSCode فقط برای خروجی اجرای خودکار (`bootstrap/dev.sh`) است، نه برای نظارت.
اجرای خودکار Termux/VSCode و حدود منابع (systemd/cgroup): به `bootstrap/README.md` در ریشه ریپو مراجعه کنید.

## 🌱 بذر اولیه از مغز + چشم‌ودستِ الگوریتمی
معماری نهایی: **مغز = مدل اصلی** (برنامه‌ریز)، **حافظه = دیتابیس مهارت‌های داشبورد** (نه مغز کوچک)، **چشم = Parser الگوریتمی** و **دست = مجری الگوریتمی** با وایت‌لیست. در تب حافظه، بخش «پلی‌بوک اولیه از مغز»: کارهای عرفی را خط‌به‌خط می‌نویسید، مغز یک بار آن‌ها را به قدم‌های Shortcut/تایپ خرد و پیش‌نویس می‌سازد؛ بعد از تأیید شما فعال می‌شوند و از آن به بعد بدون صدازدن مغز اجرا می‌شوند. کارهای تازه اول قدم‌به‌قدم با مغز انجام و بعد به مهارت تبدیل می‌شوند (مدیریت بر اساس استثنا: فقط خطا/تازگی به مغز برمی‌گردد).
